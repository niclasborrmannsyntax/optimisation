# I18N Leitfaden für mehrsprachige Webseiten

## 1. Was ist I18N?

I18N (Internationalization) bedeutet, eine Webseite so zu gestalten, dass sie einfach in verschiedene Sprachen übersetzt und für unterschiedliche Regionen angepasst werden kann.

I18N vs. L10N:

- **I18N (Internationalization)**: Technische Vorbereitung der Anwendung für mehrsprachige Unterstützung
- **L10N (Localization)**: Tatsächliche Übersetzung und kulturelle Anpassung für spezifische Sprachen/Regionen

Ziele von I18N:

- Einfache Verwaltung von Übersetzungen
- Schnelle Erweiterung auf neue Sprachen
- Bessere SEO für verschiedene Sprachmärkte
- Verbesserte Nutzererfahrung für internationale Zielgruppen

## 2. Grundkonzepte und Begriffe

### Sprach-Codes (Language Codes)

- Format: ISO 639-1 (z. B. `de`, `en`, `fr`, `es`)
- Mit Region: `de-DE`, `en-US`, `en-GB`, `pt-BR`
- BCP 47 Standard wird von Browsern und Suchmaschinen empfohlen

### Locale (Gebietsschema)

Ein Locale definiert eine Sprach-/Kulturkombination:

- Sprache: de (Deutsch)
- Region: DE (Deutschland)
- Variante (optional): z. B. Schriftsystem

Beispiele:

- `de-DE`: Deutsch (Deutschland)
- `de-AT`: Deutsch (Österreich)
- `de-CH`: Deutsch (Schweiz)

### Plural-Regeln und Grammatik

Verschiedene Sprachen haben unterschiedliche Pluralisierungsregeln:

- Englisch: singular / plural (1 item, 2 items)
- Deutsch: singular / plural (1 Element, 2 Elemente)
- Russisch: 5 verschiedene Pluralformen

### Textrichtung (RTL / LTR)

- LTR (Left-to-Right): Deutsch, Englisch, Französisch
- RTL (Right-to-Left): Arabisch, Hebräisch, Persisch

## 3. Dateistruktur für Übersetzungen

### Organisierende Struktur (empfohlen)

```
src/i18n/
├── index.ts
├── locales/
│   ├── de/
│   │   ├── common.json
│   │   ├── landing.json
│   │   ├── about.json
│   │   └── navigation.json
│   └── en/
│       ├── common.json
│       ├── landing.json
│       ├── about.json
│       └── navigation.json
```

### Namespaces (Kategorien)

- `common`: Allgemeine UI-Elemente (Button, Header, Footer)
- `landing`: Landingpage-spezifische Texte
- `about`: About-Page-Inhalte
- `navigation`: Navigationsmenü-Texte
- `errors`: Fehlermeldungen

**Vorteil**: Bessere Organisation und schnellere Ladetzeiten (nur benötigte Namespaces laden)

### JSON-Struktur (Flach vs. Verschachtelt)

**Flache Struktur (empfohlen für Performance):**

```json
{
  "header.title": "Willkommen",
  "header.subtitle": "Optimiere deine Website",
  "button.cancel": "Abbrechen",
  "button.submit": "Absenden"
}
```

**Verschachtelte Struktur:**

```json
{
  "header": {
    "title": "Willkommen",
    "subtitle": "Optimiere deine Website"
  },
  "button": {
    "cancel": "Abbrechen",
    "submit": "Absenden"
  }
}
```

## 4. Translation-Keys benennen

### Best Practices

- Kurz und aussagekräftig: `button.submit` statt `the_button_to_submit_a_form`
- Hierarchie mit Punkt-Notation: `page.section.element`
- Kleinschreibung und Bindestriche: `error-message` statt `errorMessage` oder `Error Message`
- Keine Nummern am Anfang
- Konsistent über alle Sprachen halten (gleiche Keys für alle Locales)

### Naming-Konventionen

- `page.title`: Seitentitel / Überschrift
- `page.description`: Seitenbeschreibung / Subheading
- `button.*`: Alle Buttons
- `label.*`: Formular-Labels
- `error.*`: Fehlermeldungen
- `success.*`: Erfolgsmeldungen
- `placeholder.*`: Input-Platzhalter
- `aria.*`: Barrierefreiheits-Texte

## 5. Implementierung mit i18n-Bibliotheken

### Beliebte Bibliotheken

#### i18next (Most Popular)

- Framework-agnostisch
- Große Ökosystem (Plugins, Tools)
- Lazy Loading, Pluralisierung, Interpolation
- Browser-Erkennung
- Community-Support

#### react-i18next (für React)

- Built auf i18next
- React Hooks (`useTranslation`)
- Suspense-Support
- TypeScript-Unterstützung

#### andere Optionen:

- `react-intl`: Facebook-Projekt, Format-basiert
- `zustand` + custom: Leichtgewichtig für kleine Projekte

### Grundsetup mit i18next

```typescript
import i18n from "i18next";
import deCommon from "./locales/de/common.json";
import enCommon from "./locales/en/common.json";

i18n.init({
  resources: {
    de: { common: deCommon },
    en: { common: enCommon },
  },
  lng: "de", // Default language
  ns: ["common"], // Default namespace
  fallbackLng: "en", // Fallback language
});
```

### Verwendung in React-Komponenten

```typescript
import { useTranslation } from 'react-i18next';

export function MyComponent() {
  const { t } = useTranslation();
  return <h1>{t('page.title')}</h1>;
}
```

## 6. Sprachenerkennung und -auswahl

### Automatische Sprachenerkennung

```typescript
// Browser-Sprache auslesen
const browserLang = navigator.language; // z. B. 'de-DE'
const primaryLang = browserLang.split("-")[0]; // z. B. 'de'
```

### Vorrangfolge (Best Practice)

1. URL-Parameter oder Route (z. B. `/de/about`, `/en/about`)
2. Nutzer-Einstellung (localStorage, Benutzerkonto)
3. Browser-Sprache (navigator.language)
4. Fallback-Sprache (z. B. 'en')

### URL-Struktur

**Empfohlen (SEO-freundlich):**

- `/de/about` → Deutsch
- `/en/about` → Englisch
- `/de/kontakt` → Deutsch
- `/en/contact` → Englisch

**Alternative (subdomain):**

- `de.example.com/about`
- `en.example.com/about`

**Nicht empfohlen (Query-Parameter):**

- `/about?lang=de` → Weniger SEO-freundlich

## 7. Pluralisierung richtig handhaben

### Verschiedene Pluralformen

```json
{
  "item_count": "Du hast {{count}} Element||Du hast {{count}} Elemente"
}
```

### Mit i18next

```typescript
const { t } = useTranslation();
t("item_count", { count: 5 }); // "Du hast 5 Elemente"
```

### Komplexe Pluralformen

```json
{
  "messages": {
    "one": "Du hast 1 Nachricht",
    "other": "Du hast {{count}} Nachrichten"
  }
}
```

## 8. Formatierung: Zahlen, Datum, Zeit, Währung

### Lokalisierte Nummer-Formatierung

```typescript
const number = 1234.56;

// Deutsch
new Intl.NumberFormat("de-DE").format(number); // "1.234,56"

// Englisch (US)
new Intl.NumberFormat("en-US").format(number); // "1,234.56"
```

### Währungen

```typescript
const currency = 99.99;

new Intl.NumberFormat("de-DE", {
  style: "currency",
  currency: "EUR",
}).format(currency); // "99,99 €"

new Intl.NumberFormat("en-US", {
  style: "currency",
  currency: "USD",
}).format(currency); // "$99.99"
```

### Datum und Zeit

```typescript
const date = new Date("2026-04-01");

// Deutsch
new Intl.DateTimeFormat("de-DE").format(date); // "1.4.2026"
new Intl.DateTimeFormat("de-DE", {
  year: "numeric",
  month: "long",
  day: "numeric",
}).format(date); // "1. April 2026"

// Englisch
new Intl.DateTimeFormat("en-US").format(date); // "4/1/2026"
```

## 9. Interpolation und Variablen

### Einfache Interpolation

```json
{
  "greeting": "Hallo {{name}}, willkommen!"
}
```

```typescript
t("greeting", { name: "Anna" }); // "Hallo Anna, willkommen!"
```

### Verschachtelte Variablen

```json
{
  "message": "{{user.firstName}} {{user.lastName}} hat eine Nachricht hinterlassen."
}
```

```typescript
t("message", {
  user: {
    firstName: "Max",
    lastName: "Müller",
  },
}); // "Max Müller hat eine Nachricht hinterlassen."
```

### Formatierung in Variablen

```json
{
  "price": "Preis: {{price, currency}}"
}
```

## 10. Barrierefreiheit (Accessibility) und I18N

### Language-Attribut setzen

```html
<html lang="de">

```

### Sprache für Seitenteile wechseln

```jsx
<p lang="en">The quick brown fox jumps over the lazy dog.</p>

```

### ARIA-Labels berücksichtigen

```typescript
<button aria-label={t('aria.close-menu')}>

```

## 11. SEO für mehrsprachige Seiten

### hreflang-Implementierung

Teile Google mit, welche Sprachvarianten verfügbar sind:

```html
<head>
  <!-- Deutsche Version -->
  <link rel="alternate" hreflang="de" href="https://example.com/de/about" />
  <!-- Englische Version -->
  <link rel="alternate" hreflang="en" href="https://example.com/en/about" />
  <!-- Standard (Fallback) -->
  <link
    rel="alternate"
    hreflang="x-default"
    href="https://example.com/en/about"
  />
</head>
```

### URL-Struktur für SEO

- Jede Sprache sollte eigene URLs haben
- Für jede Sprache einzigartiger Meta-Content (Title, Description)
- Kanonische URLs korrekt setzen

### Meta-Tags pro Sprache

```jsx
<SEO
  title={t("page.title")} // "Über uns" für Deutsch, "About Us" für Englisch
  description={t("page.description")}
  canonicalUrl={`/de/about`} // oder `/en/about`
  lang="de" // wichtig für Suchmaschinen
/>
```

## 12. Umgang mit fehlenden Übersetzungen

### Strategien

1. **Fallback-Sprache**: Fehlt eine Übersetzung, wird die Fallback-Sprache (meist Englisch) verwendet
2. **Key als Fallback**: Falls keine Übersetzung existiert, wird der Schlüssel angezeigt (z. B. `page.title`)
3. **Warnung in der Entwicklung**: In Entwicklungsumgebung vor fehlenden Keys warnen

### Konfiguration mit i18next

```typescript
i18n.init({
  fallbackLng: "en",
  fallbackNS: "common",
  saveMissing: true, // Fehlende Keys speichern
  missingKeyHandler: (lngs, ns, key) => {
    console.warn(`Missing translation: ${key}`);
  },
});
```

## 13. Lazy Loading von Sprachen

### Problem

Alle Übersetzungen auf einmal laden vergrößert das Bundle.

### Lösung: Code-Splitting

```typescript
i18n.addResourceBundle("de", "common", deCommon);
i18n.addResourceBundle("en", "common", enCommon);

// Später, bei Bedarf:
i18n.addResourceBundle("fr", "common", frCommon);
```

### Mit dynamischem Import

```typescript
async function loadLanguage(locale) {
  const messages = await import(`./locales/${locale}/common.json`);
  i18n.addResourceBundle(locale, "common", messages.default);
}
```

## 16. Glossar wichtiger Begriffe

- **I18N**: Internationalization - Technische Vorbereitung für Mehrsprachigkeit
- **L10N**: Localization - Tatsächliche Übersetzung für Sprache/Region
- **Locale**: Sprach- und Kulturkombination (z. B. de-DE, en-US)
- **Fallback**: Ausweich-Sprache, wenn eine Übersetzung fehlt
- **Namespace**: Kategorie von Übersetzungen (z. B. common, landing)
- **Translation Key**: Eindeutiger Schlüssel für einen zu übersetzenden Text (z. B. button.submit)
- **Pluralization**: Regelwerk zur Deklination von Nomen
- **Interpolation**: Einsetzen von Variablen in Übersetzungstexte
- **hreflang**: HTML-Tag zur Angabe alternativer Sprachvarianten
- **RTL/LTR**: Right-to-Left / Left-to-Right - Textrichtung

## 17. Häufige Fehler und Lösungen

### Fehler 1: Gleiche Keys in verschiedenen Dateien

**Problem**: Dasselbe Wort in mehreren Namespaces definiert
**Lösung**: Zentrales Namespace für häufig verwendete Keys (z. B. `common`)

### Fehler 2: HTML im Translation-Text

**Problem**: `<strong>Wichtig:</strong> Bitte beachten`
**Lösung**: HTML in Komponente auslagern oder i18n-HTML-Support nutzen

### Fehler 3: Hardcodierte Strings in Komponenten

**Problem**: `return <h1>Willkommen</h1>` statt `t('page.title')`
**Lösung**: Code-Review und Linter-Regeln implementieren

### Fehler 4: Fehlende Pluralisierung

**Problem**: "Du hast 1 Elementee" oder "Du hast 2 Element"
**Lösung**: Pluralisierungsregeln korrekt in JSON definieren

### Fehler 5: Ignorieren kultureller Unterschiede

**Problem**: Deutsche Ausdrücke 1:1 ins Englische übersetzen
**Lösung**: Muttersprachler reviewen lassen, kulturelle Nuancen beachten
